# Cocktail architecture and decisions

How the system fits together and why. Plan and requirements are in
[`docs/QUEST_PRD.txt`](docs/QUEST_PRD.txt), live progress in [`docs/STATUS.md`](docs/STATUS.md),
and setup in [`README.md`](README.md).

Each decision has a status:

- **Merged**: in `main` and working (evidence label given).
- **Proposed**: in an open PR, or recommended from measurements but not built yet.
- **Open**: not decided.

Evidence labels follow the team convention: hardware-tested, mocked, replayed, simulated,
untested. Last updated 2026-10-24.

## System overview

```
 Quest 3S (Unity, thin client)                   Laptop hub (Python 3.12, RTX 5070 Ti Laptop 12 GB)
 ─────────────────────────────                   ─────────────────────────────────────────────────
 mic audio  ── /ingest/audio (binary) ──────────▶ ingest ─▶ 10 s audio ring (16 kHz, headset clock)
 camera JPEG ─ /ingest/video (binary) ──────────▶ ingest ─▶ newest frame only ─▶ vision (SAM 3)  [C5]
 head pose,  ─ /ingest/pose  (JSON)  ───────────▶ ingest ─▶ 10 s pose buffer (yaw, pitch)
 input                                                         │
                                                               ▼
                                                 separate: 2 voices + residual, labels   [C3]
                                                               │ per-mic band levels
                                                               ▼
                                                 locate: bearing from head movement      [C4]
                                                               │
 labels, arrows ◀── /events (JSON: sources, state) ◀──── sources (label + bearing + level)
 3D playback    ◀── /audio/out (binary, 48 kHz)    ◀──── chosen sound (E1, not built)
```

The mock headset (`hub/mockclient`) replaces the left column for testing without a headset.

## Decisions

### D1. The laptop hub does all processing; the headset is a thin client
**Merged** (PRD). The Quest streams sensors and renders results. Models run on the laptop GPU.
- **Why:** the models (separation, SAM 3, SAM Audio) need a desktop-class GPU; the headset
  can't run them.
- **Cost:** network delay and jitter. Mitigations: separate channels, small buffers, USB or a
  private hotspot.

### D2. Hub stack: Python 3.12, one uv project in `hub/`, one folder per task
**Merged** (PRs #10, #15). Packages: `protocol/` (A2), `ingest/` (B3), `mockclient/` (B4),
`separate/` (A6/C3); `locate/` (A8/C4) is in review.
- **Why:** the ML ecosystem is Python. One project with one lockfile avoids version drift.
  One owner per folder keeps parallel work from conflicting (PRD section 14).
- **GPU dependencies are an opt-in group** (`uv sync --group gpu`): PyTorch built for CUDA
  12.8, ClearVoice, transformers. That way the 8 GB dev laptop and CPU-only machines aren't
  forced to install them.

### D3. Wire protocol: WebSockets, separate channels, frozen schema
**Merged** (PR #10, A2; C# generated by `python -m protocol.export`).
- **Separate sockets** for audio, video, pose/input, events and audio-out, so a large video
  frame never delays audio.
- **Binary framing:** 4-byte header length, JSON header, then the raw payload.
- **Every client message carries `seq`, `device_ts_us` (headset clock) and `epoch`** (which
  increments on reconnect).
- **The schema is frozen:** changes only by team agreement.
- **Audio chunk timestamp = capture time of the chunk's first sample.** The hub assumed this
  (PR #15) and the Quest client sets it this way (PR #18, `MicStreamer.cs`).

### D4. One clock: the headset's; audio converted to 16 kHz at ingest
**Merged** (PR #15, simulated).
- **All hub data is indexed by `device_ts_us`.** Audio and head pose line up without
  converting between clocks.
- **Audio is resampled to 16 kHz at ingest,** since the models run at 16 kHz. The resampler
  keeps its state between chunks, so chunk boundaries add no artifacts.
- **Its 12-sample (0.75 ms) lag is subtracted from the buffer timestamps.** Without that
  correction, separation scoring was off by 25 dB (found and fixed in PR #19).

### D5. Rolling buffers: 10 s of audio and pose, only the newest video frame
**Merged** (PR #15, simulated).
- **Why 10 s:** enough for 2 s separation windows and the 5 s replay (D3 task), and the PRD's
  privacy rule ("live buffer only, 10 s").
- **Video keeps only the latest frame.** SAM 3 is slower than the camera, so older frames are
  dropped and counted, never queued.
- **Gaps up to 2 s are filled with silence** so timing stays correct. A reconnect, a clock
  jump or a longer gap resets the buffers.
- **Malformed messages are counted and dropped,** never allowed to close the connection.

### D6. GPU budget: 12 GB, not 16 GB
**Merged** (PRs #13, #24; hardware-tested). The live machine's RTX 5070 Ti **Laptop** GPU has
12 GB (11.9 GiB usable). It's Blackwell, so it needs PyTorch built for CUDA 12.8 or newer.

| Model | Use | GPU memory | Speed |
|---|---|---|---|
| MossFormer2 + AST labels | live separation (C3) | ~1.1 GB | ~460 ms per 1 s hop |
| SAM 3 image model | outlines (C5) | ~4.0 GB | ~320 ms per frame + ~80 ms per prompt |
| SAM Audio small-tv, core parts only | replay (D3 task) | ~4.4 GB peak | ~2.1 s per 5 s clip per sound |
| Gemma 4 E2B, 4-bit | later | 2.9 GB + KV cache (official table) | not measured |

- **The first three fit together: about 9.5 GB.**
- **SAM Audio fully loaded takes 22.3 GB.** Only its core parts may go on the GPU (D10).
- **Full-precision Gemma, SAM Audio base/large, and the SAM 3.1 tracker don't fit or don't work** (D9).

### D7. Live separation: MossFormer2 on sliding windows, the residual is "everything else"
**Merged** (PR #19, A6/C3; hardware-tested on simulated audio).
- **How it works:**
  - MossFormer2_SS_16K (Apache-2.0) splits two voices from 2 s windows every 1 s.
  - Overlapping halves are cross-faded, and voice order is kept by matching the overlap.
  - Stream 3 is the mix minus the two voices: music and other sounds.
- **Labels:** AST (AudioSet, 527 classes) labels each stream, mapped to speech / music /
  alarm / siren / other and smoothed across hops.
- **Results:**
  - **+17.8 / +17.1 / +17.5 dB** on a simulated 2 talkers + music scene; the target was +8 dB.
  - Labels correct.
  - A listening check confirmed the voices are well separated.
- **Why MossFormer2:** best measured quality of the candidates. Waveformer has no speech or
  general music class; GTCRN only enhances speech. It's fast enough for 1 s hops on this GPU.
- **One talker, or none:** MossFormer2 always outputs two voices, so with a single talker it
  splits that person across both voice streams. Two gates fix this (PR #26):
  - **Direction gate:** if the two voice streams arrive from the same direction (their
    left/right level differences, 1–8 kHz, differ by less than 4.5 dB), they're one source.
    The voice is merged into the slot it already occupied.
  - **Speech gate:** a voice stream that doesn't sound like speech moves into the residual.
- **Why direction:** level correlation and voice fingerprints (WavLM speaker embeddings) were
  measured first and couldn't tell one split talker from two real ones, including a
  same-gender pair.
- **The separator does not decide identity across pauses.** It keeps a voice in its stream
  while it continues; whether the next voice after a pause is the same person is tracking's
  job (D1), using world bearing (D8). Head-relative directions drift as the head turns, so a
  direction memory inside the separator made single talkers hop between streams.
- **Scenario suite** (`python -m separate.suite`, 11 simulated scenes):
  - two talkers, including two men and music louder than the speech: +17 to +22 dB;
  - one talker: +9 to +16 dB in a single stream;
  - three voices: the third ends up in the residual.
- **Limits:**
  - About 1–2 s of delay: fine for labeling and locating, too slow for live listening.
  - At most 2 voices, plus 1 residual.
  - Two talkers standing in the same direction get merged.
  - The 4.5 dB threshold is tuned for ear-level mics and needs re-tuning on the 3S.
  - Clean read speech in the tests, so expect lower scores on real room audio.

### D8. Locating: bearing from natural head movement, using per-mic levels of each stream
**Proposed** (PR #11 A8 estimator, by Lalitha; PR #21 C4 wiring, simulated).
- **Inputs:** separation produces each stream as heard at each mic (spectrogram masks applied
  to every mic). It then computes band levels at 20 Hz in the estimator's 5 bands
  (500 Hz – 8 kHz).
- **Processing:** the estimator matches how those levels change as the head turns, giving a
  360° bearing in the world frame. Convention: 0 = initial forward, + = right.
- **Bearings are withheld until the estimator has seen enough head movement.**
- **Simulated errors:** 40° / 9° / 16°. Most of the error comes from the estimator's head model
  itself. It also reports full confidence when wrong. Findings are posted on PR #11.
- **Open:**
  - the 3S mics aren't at ear positions, so the mic angles and gain table need calibrating
    from a real 3S recording (C2);
  - audio channel order (left/right) is still unconfirmed on the headset.

### D9. Vision: the SAM 3 image model per frame, not the SAM 3.1 tracker
**Proposed** (from A3 measurements, hardware-tested; C5 not built).
- **SAM 3 image model works on Windows** with the community `triton-windows` package. It runs
  with full-precision weights under bf16 autocast, as upstream does; converting the weights to
  bf16 breaks it.
- **The SAM 3.1 tracker needed three Windows workarounds,** then ran at ~15.5 s per frame and
  **crashed Windows twice** (bugcheck 0x00020001). Don't use it on this machine.
- **Prompt wording matters:** "child" scored 0.96, "person" only 0.27 on the same photo. C5
  should try several prompts or lower the threshold.
- **Expect ~2.5 frames per second.** Outlines will lag behind moving people.

### D10. Clean replay: replay MossFormer2's stream; SAM Audio is an optional cleaner
**Proposed** (from A3 measurements and a listening test; D3 task not built).
- **SAM Audio small-tv only fits if its core parts go on the GPU.** Those are the codec, the
  T5 text encoder and the DiT, ~4.4 GB peak.
- **Leave the unused parts on the CPU.** With text prompts and one candidate, the span
  predictor, the judge/CLAP rankers and the vision encoder aren't used.
- **Listening test:** text prompts ("a man speaking") removed the music from the voices, but
  **did not separate the two voices from each other.** MossFormer2 does. SAM Audio's SI-SDR
  was low (+1.9 / +5.4 / +2.5 dB), partly because the metric penalizes generative output.
- **Recommendation:** replay the last 5 s of the chosen MossFormer2 stream. Optionally run SAM
  Audio on that single-voice stream with a "speech" prompt to remove leftover noise (~2 s).
  Visual prompting (the speaker's SAM 3 outline) is the `-tv` model's strength, worth trying
  once camera frames flow.

### D11. Gemma stays off the M2 critical path
**Proposed.**
- **What decides M2:** separation, labels and locating. A language model can't separate audio
  or compute bearings.
- **Where Gemma fits:** describing the scene to the wearer from the hub's sources and the
  camera.
- **Memory:** only 4-bit E2B (2.9 GB) plausibly fits beside the live models.
- **Team decision already made:** run Gemma directly, not through the Gemini API
  (`.agents/decisions.md`).

### D12. Test without the headset: simulated sessions, a replayer, and scoring commands
**Merged** (PRs #15, #19, #23).
- **Simulator** (`mockclient.simulate`):
  - places mono sounds at world bearings and renders two ear-level mics on a turning head
    (Woodworth delay plus a 5-band spherical-head shadow);
  - writes 50 Hz head poses and per-source ground truth.
- **Replayer** (`mockclient.replay`): streams any session into the hub in real time over the
  real protocol.
- **Scoring:** `separate.score` (SI-SDR improvement and labels) and `locate.score_live`
  (bearing error, in PR #21).
- **Demo audio:** `mockclient.demo_stems` makes reproducible demo clips.
- **Caveat:** the simulator assumes ear-level mics and no room echo. Real accuracy has to be
  measured on 3S recordings.

### D13. Model weights and recordings never go in git
**Merged.**
- **Weights:** downloaded at runtime to `hub/checkpoints/` (gitignored) or the Hugging Face
  cache. Sessions go in `hub/sessions/` (gitignored).
- **Gated models** (SAM 3, SAM Audio): each person requests access with their own Hugging Face
  account and logs in with their own token.
- **SAM Audio's first load is large:** ~28 GB of downloads, including companion models.
- **After a crash or interrupted download, verify the cache.** Corrupted files have kept their
  correct size.
